# 종성(받침) 획 손실 — 진단과 개선 실험 로그

**목표**: 기존 성능(한글 전체/단문/장문 CER, 영어 CER)을 유지하면서 **겹받침 오류율**을 낮춘다.
수단은 VAE 추가 finetune / Eruku(T5) 재적응 / 추론측 수정 중 원인이 지목하는 것.

이 문서는 **진행 중**이다. 측정 → 원인 가설 → 통제 실험 → 채택/기각 순으로 계속 덧붙인다.
결론만 필요하면 README 「알려진 이슈: 종성 획 손실」 절을 보면 된다.

- 기준 모델: `finetune_runs/eruku_short_fullmse/checkpoint_step_030000.pth` (T5) +
  ckpt 내장 VAE(= `finetune_runs/vae_korean_full_mse/vae_s28000`)
- 리더: `finetune_runs/aux_htr_ko/htr_s20000`
- 측정 스크립트: `experiments/jong_stroke_loss.py`, `experiments/jong_gen_loss.py`

> **지표 극성 규약**: 이 문서의 모든 수치는 **높을수록 나쁨(오류)** 으로 통일한다.
> VAE 쪽 `missing`, 생성 쪽 `오류율`(= 1 − 음절정확도), 회귀의 종속변수도 전부 오류다.
> 따라서 **회귀 β 가 양수면 나쁘게 만드는 요인**이다. (극성이 섞여 있으면 "복잡할수록 나쁘다"는
> 결론과 표의 대소가 반대로 보여 오독하기 쉽다 — 실제로 그런 혼선이 있었다.)
> 단위는 섞여 있으니 주의: **자모 단위 오류율**과 **음절 단위 오류율**은 절대값끼리 비교하지 말고
> 각자의 대조군 대비 **배율**로 읽을 것.

## 용어

완성형 음절 = 초성 + 중성 + 종성. 종성을 네 갈래로 나눈다.

| 갈래 | 내용 |
|---|---|
| 없음 | 받침 없음 (가, 나, 도…) |
| 홑받침 | ㄱㄴㄷㄹㅁㅂㅅㅇㅈㅊㅋㅌㅍㅎ |
| 쌍받침 | ㄲ, ㅆ (같은 자음 2개) |
| 겹받침 | ㄳㄵㄶㄺㄻㄼㄽㄾㄿㅀㅄ (다른 자음 2개) |

## 측정 1 — VAE 재구성에서의 획 손실 (픽셀 정밀)

**왜 VAE 부터인가.** 한글 fidelity 의 하드상한은 VAE 재구성 한계다(→ [`VAE_ROBUSTNESS.md`](VAE_ROBUSTNESS.md)).
생성물은 반드시 VAE 디코더를 통과하므로, 생성에서 보이는 손실 중 얼마가 VAE 탓인지 먼저 분리해야 한다.

**왜 이 측정이 정확한가.** roundtrip 출력은 입력과 **픽셀이 정렬**된다. 그래서 폰트 advance 로
음절 창을 잘라 GT 잉크와 1:1 비교할 수 있다. (생성물은 폭·자간이 달라 이렇게 못 잰다 → 측정 2)

- 폰트 16종 (train 8 + held-out 8), 120 라인, **n = 23,039 음절**
- `missing` = GT 잉크인데 복원에서 사라진 비율 / `extra` = 없던 자리에 생긴 비율
- `아래 40%` = 그 음절 잉크 bbox 의 하단 40% (= 받침이 사는 자리)

### 릴리즈 VAE (`vae_korean_full_mse/vae_s28000`)

| 종성 유형 | n | missing↓ | extra | ink_keep | IoU↑ | 아래40% missing↓ |
|---|---|---|---|---|---|---|
| 없음 | 3,312 | 0.054 | 0.055 | 1.001 | 0.899 | 0.048 |
| 홑받침 | 17,279 | 0.077 | 0.073 | 0.996 | 0.863 | 0.081 |
| 쌍받침 ㄲㅆ | 1,280 | 0.098 | 0.086 | 0.987 | 0.835 | **0.131** |
| 겹받침 ㄳㄵ… | 1,168 | 0.100 | 0.093 | 0.993 | 0.828 | 0.115 |

### 원본 영어 VAE (`blowing-up-groundhogs/emuru_vae`) — 한글 적응이 벌어준 폭

| 종성 유형 | missing↓ | IoU↑ | 아래40% missing↓ |
|---|---|---|---|
| 없음 | 0.134 | 0.786 | 0.125 |
| 홑받침 | 0.217 | 0.680 | 0.222 |
| 쌍받침 ㄲㅆ | 0.236 | 0.662 | 0.281 |
| 겹받침 ㄳㄵ… | 0.265 | 0.624 | 0.297 |

### 읽기

1. **손실은 받침 유무에 비례한다.** 종성 없음 대비 홑 +43% / 쌍 +81% / 겹 +85%.
2. **손실은 받침 위치에 집중된다.** 음절 전체 missing 격차는 0.054→0.100(1.9배)인데,
   받침 자리로 좁히면 0.048→0.131(**2.7배**). 획이 골고루 뭉개지는 게 아니라 아래쪽이 무너진다.
3. **증발이 아니라 이동이다.** `ink_keep ≈ 1.0` 이고 `missing ≈ extra` — 잉크 총량은 보존되는데
   자리가 어긋난다. 즉 "획이 지워진다"보다 "획이 뭉개져 밀린다"가 물리적으로 맞는 서술.
4. **한글 적응은 이미 2.4~2.7배 벌었지만 격차 구조는 그대로다.** 겹받침 0.265→0.100.
   유형 간 상대 격차(없음 대비 +85%)는 원본 VAE(+98%)와 크게 다르지 않다 →
   같은 방식의 VAE finetune 을 더 돌리는 것으로 격차가 저절로 사라질 것 같지 않다.
5. **폰트 과적합 아님.** held-out 폰트가 오히려 약간 더 좋다 (쌍받침 test 0.088 vs train 0.108).

**같은 픽셀 예산에 담아야 할 획이 많아서**라는 쪽에 무게가 실린다.

## 측정 2 — 생성 경로에서의 획 손실 (자모 단위)

생성물은 GT 와 픽셀 정렬이 안 되므로 HTR 리더로 읽고 **음절 정렬(Needleman-Wunsch) 후 자모 분해**해
센다. 받침이 뭉개지면 리더는 받침 없는/다른 음절로 읽는다(한→하, 닭→닥).

세 경로를 **같은 텍스트·같은 지표**로 재서 책임을 분해한다:

| 경로 | 무엇을 재나 |
|---|---|
| GT 렌더 | 리더 자체 오차 = 바닥 |
| GT → VAE 복원 | VAE 가 만드는 손실 (상한) |
| 생성 | 최종 손실 (T5 + VAE) |

### 통제 조건: 종성 유형 균등 (유형별 450 음절, 150 라인, cfg=1.0)

전부 **오류율(↓ 좋음, 높을수록 나쁨)**. 음절오류율 = 1 − 음절정확도.

| 종성 유형 | 경로 | 음절오류율 | 종성삭제율 | 종성오치환 | 초성오류 | 중성오류 |
|---|---|---|---|---|---|---|
| 없음 | GT렌더 | 0.053 | — | — | 0.022 | 0.031 |
| | VAE복원 | 0.076 | — | — | 0.027 | 0.047 |
| | **생성** | **0.271** | — | — | 0.133 | 0.180 |
| 홑받침 | GT렌더 | 0.024 | 0.000 | 0.011 | 0.004 | 0.011 |
| | VAE복원 | 0.100 | 0.007 | 0.053 | 0.022 | 0.040 |
| | **생성** | **0.289** | **0.042** | **0.140** | 0.140 | 0.160 |
| 쌍받침 ㄲㅆ | GT렌더 | 0.031 | 0.002 | 0.018 | 0.004 | 0.016 |
| | VAE복원 | 0.087 | 0.004 | 0.044 | 0.042 | 0.044 |
| | **생성** | **0.280** | **0.056** | **0.149** | 0.127 | 0.144 |
| 겹받침 ㄳㄵ… | GT렌더 | 0.044 | 0.000 | 0.036 | 0.007 | 0.013 |
| | VAE복원 | 0.156 | 0.013 | 0.118 | 0.031 | 0.044 |
| | **생성** | **0.507** | **0.058** | **0.404** | 0.164 | 0.191 |

> **조건 주의**: 유형별 표본을 맞추려고 코퍼스 음절을 무작위로 나열한 텍스트를 썼다(OOD).
> 절대 수준은 실제 문장보다 나쁘다 — 읽어야 할 것은 **유형 간 상대 차이**다.
> 자연 분포(코헤런트 문장) 기준 절대 수치는 아래 별도 절에 적는다.

### 읽기

1. **취약한 건 쌍받침이 아니라 겹받침이다.** 쌍받침 음절오류율 0.280 은 홑받침 0.289 와 동급이고
   종성 없음(0.271)과도 사실상 같다. **겹받침만 0.507** 로 21.8~23.6%p 높다(홑받침의 1.8배).
2. **지배적 실패 모드는 삭제가 아니라 오치환.** 겹받침 삭제 5.8% vs **오치환 40.4%**(홑받침의 2.9배).
   두 자음 중 하나를 잃어 다른 받침으로 읽히는 형태(ㄺ→ㄱ/ㄹ)가 압도적이다.
3. **손실은 종성에만 국한된다.** 초성·중성 오류는 유형 무관하게 13~19%로 평탄하다.
   즉 겹받침 음절이 통째로 어려운 게 아니라 **받침 슬롯만** 무너진다.
4. **책임 분해 (겹받침 오치환)**: 리더바닥 3.6% → VAE 11.8% → 생성 40.4%.
   VAE 가 **+8.2%p**, T5 가 **+28.6%p**. 겹받침에 한해 **손실의 약 3/4 이 생성 단계**에서 발생한다.
   → **VAE 만 더 키우는 접근은 이 문제의 1/4 밖에 못 건드린다.**

## 검증 1 — H1(획 수) / H2(학습 빈도), VAE 측

재분석 스크립트: `experiments/jong_hypotheses.py` (새 생성 없음, 측정 1 의 음절별 덤프만 사용).
음절 1,440종 (측정 1 에서 표본 20개 이상 모인 음절).

**획 수 정의**: 자모별 표준 획수 합(ㄱ1 ㄴ1 ㄷ2 ㄹ3 ㅁ3 ㅂ4 ㅅ2 ㅇ1 ㅈ2 ㅊ3 ㅋ2 ㅌ3 ㅍ4 ㅎ3,
쌍자음 2배, 겹받침·복합모음은 구성 자모 합).

### 단변량 상관 (VAE missing)

| 설명변수 | Pearson | Spearman |
|---|---|---|
| **획 수** | **+0.541** | **+0.576** |
| 자모 수 | +0.489 | +0.342 |
| GT 잉크 px | +0.430 | +0.439 |
| log10(코퍼스 빈도) | −0.330 | −0.271 |

획 수가 단독으로 가장 강하다. 단 획 수 ↔ 잉크px 상관이 +0.833, 획 수 ↔ 빈도도 교란
(희귀 음절은 획도 많다: 최희귀 25% 평균 7.8획 vs 최빈 25% 6.0획) → 다변량으로 분리해야 한다.

### 표준화 다중회귀 `missing ~ 획수 + log빈도 + 겹받침더미`

| 변수 | β |
|---|---|
| 획 수 | **+0.454** |
| 겹받침 더미 | +0.146 |
| log 빈도 | −0.127 |

R² = 0.327.

### 획 수를 통제한 겹−홑 차이

| 획수 구간 | 없음 | 홑받침 | 쌍받침 | 겹받침 |
|---|---|---|---|---|
| 0~6 | 0.051 (150) | 0.068 (383) | 0.081 (4) | 0.085 (4) |
| 7~8 | 0.064 (45) | 0.080 (435) | 0.086 (19) | 0.099 (18) |
| 9~10 | 0.066 (9) | 0.086 (209) | 0.101 (34) | 0.102 (30) |
| 11~12 | 0.067 (3) | 0.085 (41) | 0.111 (17) | 0.102 (19) |
| 13+ | — | 0.083 (12) | 0.096 (6) | 0.089 (2) |

통제 전 겹−홑 = **+0.0229** → 획수 통제 후 = **+0.0172**.

### 판정 (VAE 측)

- **H1 = 주 원인으로 채택.** 획 수가 지배적 설명변수(β +0.454)이고, 종성 갈래보다 획 수가
  더 잘 설명한다. 즉 VAE 의 받침 손실은 "받침이라서"가 아니라 **같은 latent 예산에 담을 획이
  많아서** 생긴다. 받침자리(아래40%) missing 도 획수 단조 증가(0.064 → 0.105).
- **다만 겹받침 고유분이 남는다.** 획 수를 통제해도 겹−홑 +0.0172(원 격차의 75%)가 남고
  더미 β도 +0.146 로 유의미하다 → 획 수만으로는 설명이 안 되는 **겹받침 특유의 요인**(두 자음이
  좌우로 눌려 들어가는 배치)이 별도로 존재한다.
- **H2 = VAE 측에서는 약함.** log빈도 β −0.127 로 셋 중 가장 작고, 빈도 4분위별 missing 은
  0.080 / 0.081 / 0.079 / 0.065 로 최빈 구간만 좋은데 그 구간은 획 수도 가장 낮다(6.0 vs 7.8)
  → 빈도 효과의 상당 부분이 획 수 교란이다.

### ⚠️ 정정: 코퍼스 빈도 ≠ 학습 노출량

처음엔 `assets/corpus` 의 **토큰 빈도**를 노출 대리변수로 썼는데 **틀렸다**. 학습 샘플러
(`custom_datasets.korean.fontset.MixedLineSampler`, `custom_datasets.korean.split.build_samplers`)는 코퍼스 빈도를
쓰지 않는다:

- `build_pools` 가 코퍼스에서 단어를 **`set` 으로** 모은다 → 빈도 정보가 그 시점에 소멸
- ko 토큰(가중치 0.45)은 그 **고유 단어 7,305개에서 균등 추출** (`rng.choice`)
- 게다가 `rand` 카테고리(가중치 0.15)가 전 폰트 교집합 음절 **2,350자에서 균등** 추출한다
  (길이 1~4, 평균 2.55) — 코드 주석에도 "코퍼스 빈도 편향 없이 모든 음절을 균등 노출"이라 적혀 있다

그래서 진짜 노출량은 해석적으로 계산해야 한다(`train_exposure()`):

```
노출(s) = 0.45 · (고유 단어풀에서 s 등장 총수 / 7305) + 0.15 · 2.55 / 2350
```

| 종성 유형 | 코퍼스 토큰% | **실 노출%** | **음절당 노출 배율(홑=1)** | 음절 수 |
|---|---|---|---|---|
| 없음 | 51.07% | 39.42% | 3.59 | 349 |
| 홑받침 | 45.93% | 55.49% | 1.00 | 1,763 |
| 쌍받침 ㄲㅆ | 2.54% | 3.15% | 0.84 | 119 |
| 겹받침 ㄳㄵ… | 0.47% | **1.94%** | **0.52** | 119 |

**결론이 크게 달라진다.** 코퍼스만 보면 겹받침이 홑받침의 1/6.5 로 굶은 것처럼 보이지만,
샘플러의 `rand` 균등 노출 덕에 실제로는 **0.52배**까지 완화돼 있다(4배 개선).
개별 종성도 마찬가지 — ㄿ 는 코퍼스에 **1회**뿐이지만 실 노출은 0.014%, ㄵ 는 코퍼스 21회 → 0.032%.
즉 **"코퍼스에 없어서 못 배웠다"는 서술은 과장**이다.

노출 변수를 코퍼스 빈도 → 실 노출로 바꿔 회귀를 다시 돌려도 결론은 그대로다:

| 변수 | β (코퍼스 빈도 사용) | β (**실 노출** 사용) |
|---|---|---|
| 획 수 | +0.454 | **+0.453** |
| 겹받침 더미 | +0.146 | +0.148 |
| log 노출 | −0.127 | **−0.140** |

R² 0.327 → 0.330. **VAE 측에서는 노출량을 제대로 재도 획 수가 3.2배 강하다.**
다만 T5 는 텍스트 조건을 직접 학습하므로 노출 효과가 VAE 와 다를 수 있다(→ 검증 2).

## 검증 2 — 생성(T5) 측 회귀: VAE 와 정반대

음절별 생성 **오류율** n=871, 설명변수는 검증 1 과 동일(획수 / log 실노출 / 겹받침 더미).
양쪽 다 오류가 종속이므로 **양수 β = 나쁘게 만드는 요인**으로 통일해 읽는다.
(정확도를 종속으로 두면 부호만 전부 반대가 된다 — 표준화 회귀에서 y → −y 는 β 부호만 뒤집고 R² 는 같다.)

| 변수 | VAE (missing 종속) | **생성 (오류율 종속)** |
|---|---|---|
| 획 수 | +0.453 (지배적) | **+0.014 (사실상 0)** |
| log 실노출 | −0.140 | **−0.146** |
| 겹받침 더미 | +0.148 | **+0.156 (최대)** |

R² = 0.057 (VAE 는 0.330). 음절 정체성만으로는 생성 오류율 분산의 6% 밖에 설명 못 한다 —
나머지는 폰트·문맥·실행 편차다. 순위는 읽되 "이게 전부"로 읽지 말 것.

**획 수 효과가 T5 에서 완전히 사라진다.** VAE 에서 3.2배 강했던 변수가 여기선 무의미하다
→ T5 의 겹받침 실패는 획 밀도 문제가 아니다. 따라서 latent 예산 증대 계열 처방은 근거가 없다.

### 노출을 통제해도 격차가 남는다

음절 **오류율** 기준(높을수록 나쁨):

| 실노출 구간 | 겹받침 | 홑받침 | 차이 |
|---|---|---|---|
| 중간 | 0.500 (n=102) | 0.291 (n=292) | **+0.209** |
| 상위 33% | 0.403 (n=13) | 0.212 (n=104) | **+0.191** |

노출이 가장 많은 구간에서도 19%p 낮다 → **"덜 봐서 그렇다"로 설명되지 않는다.**

### 결정적 단서: byte 토크나이저에 종성 구조가 없다

모델의 텍스트 조건은 **byT5-small = UTF-8 바이트 단위**다(`models/eruku.py:70`).
한글 완성형은 3바이트인데, 같은 종성을 쓰는 음절들이 **바이트를 하나도 공유하지 않는다**:

| 음절 | 바이트 |
|---|---|
| 닭 | `eb 8b ad` |
| 읽 | `ec 9d bd` |
| 맑 | `eb a7 91` |
| 붉 | `eb b6 89` |
| 흙 | `ed 9d 99` |

완성형 코드는 `0xAC00 + 초성·588 + 중성·28 + 종성` 인데 28 이 64(바이트 경계)와 안 맞아,
종성 정보가 2·3 바이트에 **비선형으로 흩어진다**. 게다가 바이트가 인접한 음절이 시각적으로 무관하다:
달 `…ac` → 닭 `…ad` 는 1 차이인데 획이 하나 통째로 붙는다. **바이트 임베딩 공간이 시각 공간과
어긋나 있다**(adversarial).

결과적으로 모델은 "ㄺ 은 이렇게 그린다"를 **일반화할 수단이 없고 음절마다 통째로 외워야 한다.**
겹받침 117자는 개별로 희귀하니 외울 기회도 적다 → 노출 통제 후에도 격차가 남는 이유가 여기 있다.
초성·중성 오류가 평탄한 것도 같은 틀로 설명된다: 초성 19·중성 21 종은 모든 음절에 등장해
바이트 패턴이 충분히 반복되지만, 종성 28 종은 mod-28 상호작용까지 얹혀 가장 성기다.

자모로 분해하면 이 구조가 복원된다:

| 표현 | 닭 | 값 | 공유 구조 |
|---|---|---|---|
| 완성형 | `eb 8b ad` | `ea b0 92` | 없음 |
| NFD (결합 자모) | U+1103 U+1161 **U+11B0** | U+1100 U+1161 **U+11B9** | 모든 ㄺ 음절이 U+11B0 을 공유 |
| 명시 분해 | ㄷㅏ**ㄹㄱ** | ㄱㅏ**ㅂㅅ** | ㄺ 이 빈번한 ㄹ·ㄱ 과 부분 공유 |

### byte 가설의 직접 검증: 음절 단위 암기인가, 종성 단위 일반화인가

byte 가설이 맞다면 모델은 **음절을 통째로 외울 뿐** 같은 종성을 공유하는 음절끼리 일반화하지
못한다. 이건 기존 데이터로 바로 가를 수 있다 — 노출 변수를 두 종류 만들어 경쟁시킨다.

- **음절 단위 노출**: 그 글자 자체를 몇 번 봤나 → 이게 이기면 **통째 암기**(byte 가설 지지)
- **종성 단위 노출**: 그 받침을 (음절 종류 불문) 몇 번 봤나 → 이게 이기면 **종성 단위 일반화됨**(반증)

| 모델 | log 음절노출 β | log 종성노출 β | R² |
|---|---|---|---|
| 둘만 경쟁 | **+0.147** | +0.094 | 0.040 |
| 전체(+획수, +겹받침더미) | **+0.152** | **−0.040** | 0.058 |

(두 노출끼리 상관 +0.347 — 충분히 분리 가능)

**음절 단위 노출이 이기고, 종성 단위 노출은 전체 모델에서 0으로 죽는다.**
→ 모델은 같은 받침을 공유하는 음절들 사이에서 **일반화하지 않는다**. byte 가설 방향은 지지된다.

단, 같은 회귀에서 **겹받침 더미가 여전히 최대(+0.180, 오류율 종속)** 다. 암기 구조만으로는 겹받침 페널티가
전부 설명되지 않는다 — 아직 이름 붙이지 못한 요인이 남아 있다. 그리고 R²=0.058 이라
음절 정체성 계열 변수 전부로 생성 오류율 분산의 6% 밖에 설명 못 한다(나머지는 폰트·문맥·실행 편차).
**순위는 읽되 크기는 믿지 말 것.**

### ⚠️ 반전: 자연 문장에서는 격차가 안 보인다

같은 측정을 **실제 문장**(coherent, n=200 텍스트, 음절 3,243)으로 돌린 결과:

| 종성 유형 | 음절수 | 음절오류율 | 종성오치환 |
|---|---|---|---|
| 없음 | 1,703 | 0.048 | — |
| 홑받침 | 1,442 | 0.074 | 0.026 |
| 쌍받침 | 85 | 0.071 | 0.024 |
| 겹받침 | **13** | 0.077 | 0.077 |

**겹받침이 3,243 음절 중 13개(0.4%)뿐이고, 그 13개는 격차가 없다.** 자연 문장에 등장하는
겹받침은 닭·값·삶·읽 같은 **빈번한 소수**라 이미 잘 외워져 있기 때문이다. balanced 조건이
잡아낸 격차는 ㄿ·ㄽ·ㄾ 처럼 **사실상 학습되지 않은 희귀 겹받침**에서 나온다.

**n=13 으로 "격차 없음"을 결론지을 수는 없다**(신뢰구간이 매우 넓다). 하지만 개입의 실효
가치를 정하려면 이 칸의 표본을 먼저 키워야 한다 → 아래 M0.

## T5 개입 후보 설계

근거 요약: T5 몫 29%p / 획 밀도 무관(β −0.014) / 노출은 부차(β +0.146, 통제 후에도 −0.19 잔존)
/ 겹받침 더미가 최대(β −0.156) / **byte 토크나이저에 종성 구조 없음**.

### M0 (선행) — 개입 가치부터 확정한다

balanced(OOD) 격차 +0.20 vs coherent(자연) 격차 없음(n=13). **개입의 실효 가치가 이 사이
어디인지 모르는 상태에서 학습을 돌리면 안 된다.** 자연 어휘를 유지하면서 겹받침 표본만 키운다:

- 코퍼스에서 **겹받침을 포함한 실제 단어**만 뽑아 문장을 구성 (랜덤 음절 나열이 아님)
- 한 라인 = 겹받침 단어 2개 + 일반 단어 2개 → **대조군이 같은 이미지에서** 나온다
  (폰트·스타일 교란 제거). 구현: `jong_gen_loss.py --texts natural_jong`
- 목표 겹받침 음절 표본 ≥300 (지표는 음절 오류율)
- 산출: "실제 어휘 조건에서 겹받침 격차 X%p" — 이게 개입 성공의 **상한 기대치**다
- 비용: 배치+KV 캐시로 ~7.5초/샘플 → 250 텍스트 ≈ 30분

**선행 관찰**: 코퍼스 고유 단어 **7,305개 중 겹받침 포함은 182개(2.5%)** 뿐이다.
실사용에서 겹받침은 이 182개 단어(닭·값·삶·읽·앉·많·젊·짧 계열)를 통해서만 등장하므로,
**실효 문제 범위는 겹받침 음절 117자 전체가 아니라 그중 실제 단어에 쓰이는 소수**다.
그 소수는 학습에서 상대적으로 자주 봤을 테니 M0 격차는 balanced 의 +0.20 보다 작을 공산이 크다.

**M0 격차가 5%p 미만이면 C1~C4 전부 보류한다.** 그 경우 실사용 영향이 미미하므로
기존 성능을 걸고 재학습할 이유가 없다.

250 라인, 겹받침 음절 **n=500** (coherent 의 n=13 대비 38배).

음절 **오류율**(높을수록 나쁨):

| 종성 유형 | 음절수 | GT렌더 | VAE복원 | **생성** | 생성 종성오치환 |
|---|---|---|---|---|---|
| 없음 | 812 | 0.006 | 0.017 | 0.106 | — |
| 홑받침 | 737 | 0.007 | 0.033 | **0.128** | 0.042 |
| 쌍받침 ㄲㅆ | 80 | 0.012 | 0.050 | 0.150 | 0.100 |
| 겹받침 ㄳㄵ… | 500 | 0.024 | 0.086 | **0.306** | **0.250** |

- **겹−홑 격차 = +0.178 (17.8%p, 홑받침의 2.4배)** — 킬 기준 5%p 를 크게 넘는다 → **C1 진행**

coherent 에서 격차가 안 보인 건 순전히 n=13 의 검정력 부족이었다.
즉 **겹받침 문제는 실제 어휘에서도 그대로 있다.**

### C1. 자모 분해 텍스트 조건 ⭐ 1순위

**무엇**: 텍스트를 T5 에 넣기 전 자모로 분해한다. 완성형 3바이트를 자모 시퀀스로 바꿔
**종성이 음절 간에 공유되는 심볼**이 되게 한다.

- **C1a (채택·구현)**: NFD 결합 자모 (닭 → U+1103 U+1161 **U+11B0**).
  받침 ㄺ 은 **한 글자로 유지**되되 음절에서 떨어져 나와, 모든 ㄺ 음절이 U+11B0 을 공유한다.
  표준 정규화라 무손실(NFC 로 정확히 복원)이고 직접 만든 규칙보다 버그 여지가 적다.
- **C1b (기각)**: 겹받침까지 쪼개기 (닭 → ㄷㅏ**ㄹㄱ**). ㄺ 이 빈번한 ㄹ·ㄱ 과 부분 공유돼
  일반화는 더 셀 수 있으나, **"받침 ㄺ" 과 "받침 ㄹ + 초성 ㄱ"(달구)이 같은 시퀀스가 되는
  모호성**이 생긴다. 경계 마커로 우회할 수 있지만 표현이 복잡해져 A/B 에서 무엇이 효과를 냈는지
  흐려진다. → 기각(2026-08-04).
  C1a 의 잔여 문제(겹받침 11종이 각자 독립 심볼이라 개별 노출이 적음)는 C1b 대신 **C2 로** 푼다.

**왜 이게 1순위인가**: 노출 통제 후 잔존 격차(+0.19)를 직접 겨냥하는 유일한 후보다.
C2 는 노출만 건드리는데 노출은 이미 통제해도 격차가 남는다는 게 측정 결과다.

**구현 지점**: 텍스트가 들어가는 곳은 두 곳뿐 —
`models/eruku.py:268`(forward) 와 `:419`(generate_batch). 공용 `_encode_text()` 로
묶고 학습·추론에 **동일하게** 적용해야 한다(불일치 시 조용히 망가짐).
byT5 는 바이트 단위라 **vocab 변경·임베딩 리사이즈 불필요**.

**비용/리스크**:
- 텍스트 바이트 2.28배(코퍼스 1000줄 실측) → encoder 시퀀스 증가. 디코더(AR latent)는 불변이라
  전체 비용 증가는 제한적이지만 **텍스트 길이 상한 확인 필요**
- 영어는 ASCII 그대로 통과 → 영어 회귀 위험 낮음
- 재적응 학습 필요(기존 재적응 관례대로 s30000 resume + 15k step)
- ⚠️ 릴리즈 클래스도 같이 고쳐야 한다 — 안 하면 HF 발행본이 학습과 다른 조건으로 돌아 무너진다

**저비용 선행 A/B**: 15k 풀 재적응 전에 **3k step 짧은 재적응**으로 C1 vs 무개입 대조.
겹받침 오류율이 안 움직이면 기각하고 C3 로 간다.

### C2. 겹받침 노출 상향 (샘플러) — 저비용 병행

**무엇**: `custom_datasets.korean.split.build_samplers` 의 `rand` 풀을 종성 균등으로 바꾸거나
`rand` 가중치(현재 0.15)를 올린다. 현재 겹받침 실 노출은 홑받침의 0.52배.

**기대치는 낮게 잡을 것**: 노출을 통제해도 격차가 +0.19 남았다 → 노출만으로는 한계가 명확하다.
단독 채택이 아니라 **C1 과 병행**할 저비용 보조로 본다. 학습 코드 변경이 1줄 수준이고
VAE 는 건드리지 않는다.

**C1b 기각 후 C2 의 역할이 커졌다.** C1a 는 ㄺ 을 음절에서 떼어내 공유 심볼로 만들지만,
그 심볼 **자체의 노출**은 여전히 적다(겹받침 실 노출 = 홑받침의 0.52배). C1b 는 ㄺ 을 ㄹ·ㄱ 으로
쪼개 그 희소성을 우회하려던 것이었는데 기각됐으므로, **희소성은 노출을 직접 올려서 푼다** —
즉 C1a + C2 가 한 세트다. C1a 단독 A/B 가 부분적으로만 들으면 이 조합을 다음 후보로 올린다.

**킬 기준**: 단독으로 겹받침 오류율 −5%p 미만이면 단독 후보에서 제외(C1 병행분으로만 유지).

### C3. 자모 보조 예측 헤드 — C1 실패 시

**무엇**: 디코더 각 latent 열에서 그 열이 속한 음절의 (초성, 중성, 종성)을 맞추는 보조 헤드를
붙여 latent 표현이 받침 정체성을 담도록 강제한다. 모델에 이미 미사용 `t5_to_ocr` 헤드
(`models/eruku.py:103`, alpha=1.0 이라 loss 미사용)가 있어 자리는 있다.

**리스크**: 열↔음절 정렬 라벨을 만들어야 하는데 자간이 균일하지 않아 정렬이 근사적이다.
C1 보다 침습적이므로 C1 이 실패했을 때만.

### C4. HTR 보조 손실 (alpha < 1.0) — 최후

`train/core.py` 가 이미 `alpha<1.0` + `ocr_checkpoint` 를 지원한다. 한글 HTR 을 리더로 걸어
생성 이미지가 읽히도록 직접 감독한다.

**리스크 큼**: VAE 학습에서 HTR 가중은 **일관되게 해로웠다**(README loss ablation:
0.00713 → 0.01048). 대상이 다르므로(그건 VAE 재구성, 이건 T5 생성) 그대로 이전되진 않지만,
전례가 나쁘고 매 스텝 VAE decode + HTR forward 가 붙어 비용도 크다. 앞의 셋이 다 실패할 때만.

### C5. latent 열 예산 증대 — ❌ 근거로 기각

"획이 많아 정보가 넘친다"는 VAE 에선 맞지만 **T5 에선 획 수 β 가 −0.014 로 0**이다.
T5 몫 29%p 를 이걸로 설명할 수 없으므로 기각한다. (VAE 몫 8%p 에 한해서는 여전히 유효한 방향)

### 평가 프로토콜 (사전 등록 — 결과 보고 후 바꾸지 말 것)

모든 후보는 아래를 **전부** 재고, 하나라도 유의하게 퇴보하면 기각한다.

| 지표 | 기준선 | 허용 |
|---|---|---|
| 한글 전체 CER | 0.126 | +0.01 이내 |
| 한글 단문(1~3) | 0.286 | +0.02 이내 |
| 한글 중문(4~8) | 0.049 | +0.01 이내 |
| 한글 장문(9~15) | 0.054 | +0.01 이내 |
| 영어 전체 | 0.031 | +0.01 이내 |
| **겹받침 음절오류율 (balanced)** | **0.473** | 개선 목표(낮출 것) |
| **겹받침 격차 (M0, 자연 어휘)** | M0 에서 확정 | 개선 목표 |

⚠️ 생성은 run-to-run 재현이 안 된다(같은 입력 3회 CER 0.035/0.031/0.074).
**n≥100 + 같은 텍스트 페어링**으로만 판정하고, 단발 수치로 채택/기각하지 말 것.

### 실행 순서

1. **M0** — 자연 어휘 겹받침 벤치마크 (~40분, GPU). 격차 <5%p 면 전체 보류
2. **C1 짧은 A/B** — 3k step 재적응 × {무개입, C1a} 대조
3. C1 유망 → 15k 풀 재적응 + C2 병행, 전체 프로토콜 평가
4. C1 실패 → C3, 그래도 실패 → C4

## 실험 1 — C1a A/B (2026-08-05): **기각**

`eruku_short_fullmse/s30000` 에서 resume, 3,000 step, 동일 예산(batch 4 × accum 8, lr 5e-5,
english-frac 0.15). 두 arm 은 `--jamo-text` 만 다르다. 1,000 step 마다 저장해 추세를 봤다.

평가는 M0(자연 어휘, 겹받침 n=500).

음절 **오류율**(낮을수록 좋음 → C1a 가 이기려면 control 보다 **작아야** 한다):

| step | control 겹 | control 홑 | control 격차 | **jamo 겹** | jamo 홑 | jamo 격차 |
|---|---|---|---|---|---|---|
| 30000 (공통 기준선) | 0.306 | 0.128 | +0.178 | 0.306 | 0.128 | +0.178 |
| 31000 | 0.280 | 0.130 | +0.150 | **0.358** | 0.138 | +0.220 |
| 32000 | 0.290 | 0.134 | +0.156 | 0.306 | 0.121 | +0.185 |
| 33000 | 0.324 | 0.148 | +0.176 | **0.326** | 0.144 | +0.182 |

### 먼저: 측정 노이즈부터 쟀다

같은 ckpt(control 33000)를 3회 반복 측정:

| | 겹받침 오류율 | 겹−홑 격차 |
|---|---|---|
| run1 / run2 / run3 | 0.324 / 0.318 / 0.322 | +0.176 / +0.174 / +0.177 |
| 평균 ± σ | 0.3213 ± **0.0031** | +0.1757 ± 0.0014 |

**노이즈 σ = 0.31%p 로 작다.** 생성이 run-to-run 재현 안 된다는 사실에도 불구하고, 겹받침
n=500 로 평균 내면 벤치마크는 충분히 정밀하다. → 이 벤치마크로 A/B 판정 가능.
(반대로 체크포인트 간 변동은 σ=2.31%p 로 **노이즈의 7.5배** — 이건 실제 학습 변동이다.)

### 판정: 기각

- C1a 오류율(0.326)은 control 33000 평균(0.321) 대비 **+0.47%p = 1.5σ**. 이득 없음, 오히려 미세하게 나쁨
- 격차도 +0.176 → +0.182 로 안 줄었다
- 추세: jamo 는 31k 에서 오류율 0.358 로 **치솟았다가 회복**한다(표현 재학습 비용이 실재하며 2k 만에 복구).
  하지만 회복 후 32k→33k(0.306→0.326)는 control(0.290→0.324)과 똑같이 악화 — **앞서는 구간이 없다**
- 사전 등록한 기준("control 평평 + jamo 상승이면 풀 재적응")을 충족하지 못함 → **15k 확장 안 함**

부수 관찰: **두 arm 모두 3k 를 더 돌리면 겹받침이 나빠진다**(오류율 31k 0.280/0.358 → 33k 0.324/0.326).
README loss ablation 의 "resume 로 예산을 늘리면 퇴보할 수 있다"(Adam 상태·lr 스케줄 재시작)와
같은 현상으로 보인다. 이 A/B 는 그 퇴보 구간 위에서 이뤄졌다는 한계가 있다.

## 실험 2 — C1a 실패의 원인 재분석: **글리프 복잡도가 진짜 설명변수**

C1a 가 안 먹힌 이유를 찾기 위해, 그동안 회귀에 **한 번도 넣지 않았던 변수**를 넣었다:
**그 글자를 VAE 가 얼마나 못 담는가**(측정 1 의 음절별 missing). 글리프 복잡도의 직접 측정치다.

M0 조건, 두 측정에 공통으로 있는 음절 n=331:

종속변수는 **음절 오류율**(양수 β = 나쁘게 만드는 요인):

| 설명변수 | 단변량 Pearson | **다중회귀 β** |
|---|---|---|
| **VAE 난이도(그 글자의 missing)** | +0.283 | **+0.221** |
| GT 잉크 px | +0.259 | +0.092 |
| 획 수 | +0.261 | +0.073 |
| log 실노출 | −0.208 | −0.033 |
| 겹받침 더미 | — | **−0.102 (부호 반전!)** |

R² = 0.100 (겹받침 더미만 쓰던 이전 모델의 0.058 에서 개선).

### 이게 뒤집는 것

**겹받침 더미의 부호가 양수(나쁨) → 음수(오히려 좋음)로 뒤집힌다.** 글리프 복잡도(VAE 난이도·잉크·획수)를
통제하면 겹받침은 더 이상 불리하지 않다. 단 이 부호 반전을 "겹받침이 홑받침보다 낫다"로 읽으면 안 된다 —
복잡도와 '겹받침임'이 거의 겹쳐 통제 후 표본이 얕고 R²=0.100 이라, **겹받침 고유 페널티가 0 에 가깝다**
정도로 읽는 것이 안전하다. **관측 오류율은 여전히 겹받침 0.306 vs 홑받침 0.128 로 2.4배다.** 즉 **"겹받침 페널티"는 독립된 현상이 아니라 "이 글자가 복잡하다"의
대리변수였다.** 겹받침이 나쁜 건 받침이 두 개라서가 아니라 **글리프가 조밀해서**다.

이것이 C1a 실패를 설명한다 — C1a 는 텍스트 조건의 **심볼 공유** 문제를 고쳤는데, 병목은
텍스트 쪽이 아니라 **조밀한 글리프를 그려내는 능력**이었다. 종성 정보는 이미 전달되고 있었다.

앞선 관찰과도 맞는다: M0 에서 겹받침 음절은 **초성 오류 0.104 / 중성 오류 0.108** 로 홑받침
(0.068 / 0.072)보다 1.5배 높다 — 받침 슬롯만 깨지는 게 아니라 **글자 전체가 어렵다**.
(balanced 조건에서는 이 차이가 평평했는데, 그건 무작위 음절 나열이라 모든 칸이 똑같이 어려웠던 탓)

### ⚠️ 이전 결론 정정

1. **"T5 는 획 밀도와 무관"(β ±0.014) → 정정.** 그 회귀는 balanced 조건이었고 VAE 난이도를
   넣지 않았다. 자연 어휘 + 복잡도 변수를 넣으면 복잡도 계열이 최대 설명변수다.
2. **"C5(latent 예산 증대)는 근거로 기각" → 철회.** 기각 근거가 위 β −0.014 였는데 그게 뒤집혔다.
   C5 는 다시 유효한 후보다.
3. **"손실은 종성 슬롯에만 국한" → 정정.** 자연 어휘에서는 초성·중성 오류도 같이 오른다.
