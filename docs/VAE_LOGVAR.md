# log_var (학습형 관측 노이즈 가중) — 원리와 실증

> `models/autoencoder_loss.py`의 `nll / exp(log_var) + log_var` 항. **논문(emuru)엔 없음.**
> 원본 코드가 물려받은 **LDM/CompVis(Stable Diffusion AE) 관례**이며, 뿌리는
> Kendall & Gal의 *learned observation uncertainty(homoscedastic)* 다.
> `train/vae_korean.py`에서는 `--logvar-weighting` 플래그로 켠다(기본 off).

---

## 1. 어디서 나온 식인가 — 가우시안 우도의 MLE

재구성 오차가 분산 σ²인 가우시안을 따른다고 가정:

```
p(x | x̂) = N(x; x̂, σ²)
-log p = (1/2σ²)·‖x - x̂‖²  +  (1/2)·log σ²  +  const
                └──── L ────┘
```

<details>
<summary><b>왜 -log p 가 저 형태가 되는가 (펼친 유도)</b></summary>

가우시안 밀도함수에 그냥 -log 를 씌워 항별로 정리한 것뿐이다.

**출발 — 가우시안 PDF:**

```
p(x | x̂, σ²) = (1/√(2πσ²)) · exp( -(x-x̂)² / (2σ²) )
               └── 정규화 상수 ──┘  └──── 종 모양 지수 ────┘
```

**-log 를 씌우면 곱이 로그로 덧셈으로 쪼개진다:**

```
-log p = -log[ 1/√(2πσ²) ]  +  ( -log exp( -(x-x̂)²/(2σ²) ) )
             └──── ① 정규화 ────┘   └────────── ② 지수 ──────────┘
```

**항 ② (지수):** log 와 exp 상쇄, 안의 부호 −가 살아남아 +가 됨

```
-log exp( -(x-x̂)²/(2σ²) ) = +(x-x̂)²/(2σ²)     ← 재구성 오차 항 = L/(2σ²)
```

**항 ① (정규화 상수):** √ 는 지수 ½ 로, 곱은 로그 덧셈으로

```
-log[ 1/√(2πσ²) ] = ½·log(2πσ²) = ½·log σ²  +  ½·log(2π)
                                  └ σ 의존 ┘   └── 상수 ──┘
```

`½ log σ²` 가 코드의 `+ s`(정규화/log-partition 항, s=log σ²), 뒤 `½ log 2π` 는 σ²·x̂ 와 무관해 `const` 로 버린다.

**합치면:**

```
-log p = (1/2σ²)·‖x-x̂‖²  +  ½·log σ²  +  const     (L=‖x-x̂‖², s=log σ² 치환 → L/eˢ + s)
```

**직관 — 왜 이 두 항인가:**
- 재구성 항 `L/(2σ²)`: 데이터를 맞추라는 압력. σ²(불확실성)이 크면 오차에 관대해짐.
- `+½ log σ²`(log-partition): 반대 압력. σ²를 무한대로 키워 위 항을 공짜로 0 만드는 걸 막는 **패널티**
  (가우시안이 넓어질수록 밀도 꼭대기가 낮아짐 = 정규화 상수가 로그로 드러난 것). 이 둘의 균형점이
  `∂/∂s=0 → σ²=L`(§2 자기보정)이다.

> D차원 등방 가우시안이면 엄밀히는 `(D/2)log σ²` 지만, 여기선 L 을 **픽셀평균 오차**로 두어 원소당 ½ 계수로
> 맞춘 것이고, 결론(σ²=L 자기보정)은 스케일에 무관하게 동일하다.

</details>

`s = log σ² = log_var` 로 두면 (σ² = eˢ):

```
-log p  ∝  L / eˢ  +  s          ← 코드의  nll/exp(log_var) + log_var
```

즉 관측 노이즈 σ²를 **상수로 튜닝하는 대신 학습 파라미터로 놓고 MLE로 동시 최적화**한다.
여기서 log_var는 **스칼라 1개(homoscedastic)** — per-pixel 불확실성이 아니라 전역 loss-스케일이다.

## 2. 장점 ① 자기보정(self-calibration): σ²가 현재 loss 스케일을 자동 추종

s에 대해 미분:

```
∂/∂s [ L·e^(-s) + s ] = -L·e^(-s) + 1 = 0   ⇒   e^(s*) = L ,  s* = log L
```

**최적 분산이 현재 재구성 오차 크기 그 자체로 수렴**한다. σ²를 손으로 정할 필요가 없다.
`+ s` 항이 핵심 규제: 이게 없으면 모델이 s→+∞ 로 보내 `L/eˢ → 0` 으로 loss를 공짜로
없애버린다. `+s`(가우시안 정규화항)가 그걸 막아 유일한 최적점을 만든다.

## 3. 장점 ② 그래디언트 스케일 정규화 (단일 항에서 유일하게 남는 실익)

네트워크 파라미터 θ에 대한 그래디언트:

```
∂loss/∂θ = (1/eˢ)·∂L/∂θ  ≈  (1/L)·∂L/∂θ        (eˢ ≈ L 이므로)
```

**그래디언트가 loss 크기로 나눠져 정규화**된다. 초기 L이 크면 감쇠, L이 줄면 eˢ도 줄어 증폭
→ 전 구간 유효 스텝이 스케일 불변. loss 최적값도 `L/e^(s*) + s* = 1 + log L` 로 **로그 압축**되어
스케일 폭주를 눌러준다.

## 4. 장점 ③ 다중 loss 항 자동 밸런싱 (원본 코드의 본래 목적)

원본 코드에서 이 nll은 **rec + htr + WID 를 다 합친 것**이고 거기에 `+ kl_weight·KL` 이 붙는다.
log_var는 **nll 뭉치 vs KL 항의 비율을 자동 조절**한다 — nll이 KL의 1000배여도 kl_weight를
손으로 안 맞춰도 된다. 이것이 SD AE에서 log_var를 쓰는 원래 이유다.

---

## 5. 우리 세팅에선 왜 거의 무의미한가 (사전 예측)

- **log_var는 nll *전체*를 감싸는 단일 스칼라** → rec-vs-htr 비율은 못 바꾼다(그건 `htr_weight` 고정).
  실험 RUN은 `htr_weight=0` 이라 nll = L1 하나뿐.
- **밸런싱 대상인 KL 가중치가 1e-6**(사실상 0) → 장점 ③(rec-vs-KL 밸런싱)이 발동할 여지가 없다.
- 남는 건 장점 ②(단일 항 그래디언트 정규화)뿐인데, **Adam이 이미 2차 모멘트로 파라미터별
  그래디언트 스케일을 정규화**하므로 상당 부분 중복 → 거의 inert.

학습 로그도 이를 뒷받침: 최종 `lv = -1.481`, 이론적 종착점 `s* = log L = log(0.030) ≈ -3.5`.
Adam이 `lr=1e-4` 로 log_var를 스텝당 ~1e-4씩만 끌어내려 **15000 step 안엔 수렴도 못 함** —
즉 loss 곡선을 천천히 로그압축만 할 뿐 VAE 파라미터엔 유의미한 방향 변화를 거의 안 준다.

## 7. 결론

log_var의 수학적 실익 3가지 — (①) 관측 노이즈 MLE로 loss 스케일 자기보정, (②) loss-크기 기반
그래디언트 정규화, (③) 다중 loss 항 자동 밸런싱 — 은 **모두 "여러 항을 섞고 KL이 유의미할 때"
빛난다**. 우리처럼 **KL≈0 · 단일 L1 항 · Adam 최적화** 상황에선 이론적으로 거의 무해·무익하고,
실측도 이를 확인했다(ko 동률, hard·en 미세 열화).

→ **기본값 off 유지.** 플래그(`--logvar-weighting`)만 남겨 재현/실험용으로 보존.
논문에 없고(코드-only), 우리 세팅에서 정당하게 생략 가능한 항이다.
